**Status:** FINAL DESIGN FREEZE FOR IMPLEMENTATION / PLAYTEST CANDIDATE  
**Scope:** World Exploration + Interaction + Resource Ecology + World Pulse + Landmark/Mystery + Known Travel + Return  
**Audience:** Game Design, UI/UX, Engineering, QA, Claude Code

# 0. Purpose of This Document

This is **not another exploration concept document**.

This document freezes the current exploration design into **one complete, deterministic, implementable vertical slice** whose purpose is to answer a single product question:

> **Is Hexoflat exploration fun because the player reads an unknown world, chooses and changes routes, uses tools/resources, lets the world answer through Will/World Pulse, learns something meaningful, and turns that knowledge into a permanent new possibility?**

The slice must be implemented before adding new exploration subsystems.

This file consolidates the following design candidates:

- Frontier Exploration & Resource Ecology;
- Region Grammar Generator;
- Resource Ecology & Discovery Rewards;
- World Pulse & Living World Director;
- Landmarks, Traces & Mystery Weave;
- Known World Travel & Expedition Planning;
- Expedition Risk, Return & Camp Consequence;
- Mechanic Development Stop Gate.

The implementation must preserve the already-working prototype primitives:

- hex grid;
- blocked hex pathfinding;
- Hero Token movement;
- route trail preview;
- green/red destination state;
- final route-length number;
- Hero Board inventory/tool tokens;
- two Hand tokens;
- token-holder equipment model;
- rotating/placing Hand or Tool token around the Hero;
- contextual interaction verbs generated by token overlap;
- existing `Take`, `Open`, `Enter` and other interaction actions;
- enemy detection → combat transition;
- existing combat implementation is called as a separate controller and is **not redesigned by this slice**.

# 1. Design Freeze / Stop Gate

## 1.1 What is frozen for v0.1

The following are the only exploration systems required for this slice:

1. organic player-facing map reveal over the existing technical grid;
2. `UNKNOWN → OBSERVED → DISCOVERED → UNDERSTOOD` discovery;
3. Path of Will movement cycle;
4. one Act per exploration Burst with movement split before/after it;
5. Gather Will → World Pulse;
6. one Scout route profile;
7. one destructible traversal type: Stone Crust;
8. one permanent topology mutation: Broken Passage;
9. three resource kinds: Medicinal Plant, Stone Fragment, Timber contract only;
10. one actual resource habitat used in the slice: Medicinal Plant;
11. one Patrol actor;
12. one Noise signal caused by Stone Crust break;
13. one regional Landmark: Broken Spire;
14. two primary Traces + one optional Trace;
15. one Mystery Question;
16. one Insight: weakened/marked stone seam recognition;
17. one recontextualized old location near Camp;
18. Trail Imprint / Route Thread;
19. one Frayed Route interruption;
20. return to Camp;
21. compact Homecoming Beat.

## 1.2 Explicitly NOT to be added before playtest

Do not add:

- weather;
- day/night;
- hunger/thirst;
- mounts;
- procedural quests;
- faction simulation;
- complex ecology;
- multiple Patrol archetypes;
- more than one Noise grammar;
- large resource economy;
- dozens of resource nodes;
- carrying-weight simulation;
- shelter building;
- campfire systems;
- resource durability decay;
- random encounter tables;
- more Landmark mysteries;
- full Mystery Weave meta-game;
- full world-map fast travel;
- advanced Travel Modes beyond those required by the slice;
- dynamic difficulty manipulation by the Living World Director.

Any proposed addition must pass the **Marginal Decision Test**:

> If the feature is removed, does the vertical slice lose a necessary and currently untestable type of player decision?

If the answer is **no**, defer it.

# 2. Player Experience Promise

The target experience is:

1. leave Camp and see only a small known world surrounded by an irregular frontier;
2. notice a distant Landmark without receiving a GPS marker;
3. choose how to approach it;
4. discover that a Stone Crust blocks a short route;
5. decide whether to go around or physically create a passage with the Pickaxe;
6. understand that breaking terrain creates both a benefit and a consequence;
7. use Gather Will knowing the world will answer;
8. optionally manipulate a Patrol through Noise and timing;
9. recognize a Medicinal Plant habitat and decide whether the detour is worth it;
10. reach the Broken Spire and learn a pattern rather than simply open a chest;
11. have that new knowledge change the meaning of a previously seen stone near Camp;
12. return through a route the player themselves discovered/created;
13. have accelerated known travel stop if the world changed;
14. physically return to Camp and see only meaningful consequences;
15. be motivated to leave again because an old place has acquired a new meaning.

The slice succeeds only if the player can explain their journey as a sequence of decisions rather than as a sequence of clicks.

# 4. Existing Systems Reused Without Rewrite

## 4.1 Existing hex grid

Keep the existing rectangular/large technical axial grid.

The player must **not** see the rectangular board boundary.

`UNKNOWN` or ungenerated territory is not drawn as dark hex cells. It is rendered as world absence/fog frontier.

## 4.2 Existing pathfinding

Keep current obstacle-aware pathfinding as the canonical movement solver.

Required extension hooks:

- query route consequences;
- invalidate after topology mutation;
- stop execution on significant reveal;
- emit canonical executed path;
- feed Trail Imprint subsystem.

## 4.3 Existing route preview

Keep:

- trail path preview;
- final destination green/red;
- final total step number.

Extend the preview only contextually with:

- known terrain consequence marker;
- known breakable shortcut hint;
- known threat crossing marker;
- optional Waypoint;
- Frayed segment indication during Known Travel.

Do not add a permanent route panel.

## 4.4 Existing interaction grammar

Preserve:

```text
Player Board token
→ Use / hold
→ token appears around Hero on Game Board
→ rotate/position token
→ overlap valid world target
→ contextual verbs appear
→ choose verb
→ validate
→ resolve
```

Examples used by this slice:

```text
Hand + Medicinal Plant → Take
Pickaxe + Stone Crust → Break Through
Hand + Trace → Inspect
Hand + Landmark interaction point → Inspect
```

The slice must not introduce a generic `Interact` menu that bypasses this grammar.

# 5. World Coordinate Convention

Use axial hex coordinates:

```ts
interface HexCoord {
  q: number;
  r: number;
}
```

Pointy-top axial neighbor convention for the fixture:

```text
E  = (+1,  0)
NE = (+1, -1)
NW = ( 0, -1)
W  = (-1,  0)
SW = (-1, +1)
SE = ( 0, +1)
```

Hex distance:

```ts
distance(a, b) = (abs(dq) + abs(dr) + abs(dq + dr)) / 2;
```

# 8. Initial World State

On `ExitCampToWorld`:

1. Hero Token appears at `(1,0)`.
2. Camp `(0,0)` is `UNDERSTOOD`.
3. six Camp-neighbor hexes are at least `DISCOVERED` where generated;
4. technical hexes beyond the frontier are not rendered as a rectangular grid;
5. `ridge_junction (2,0)` may be `OBSERVED` as the immediate eastward continuation;
6. Broken Spire is allowed to create a **silhouette/bearing promise**, but its exact coordinate is not shown;
7. Patrol remains hidden until normal perception reveals it;
8. Stone Crust may be visible as a terrain barrier when the junction is observed;
9. Old marked ridge is visible but its mark has no known meaning.

The starting map should visually read as an irregular island of known space, not as a board with fogged cells.

# 9. Discovery State Machine

```ts
type DiscoveryState = 'UNKNOWN' | 'OBSERVED' | 'DISCOVERED' | 'UNDERSTOOD';
```

`EXPLOITABLE` remains future/candidate and is not required as a separate runtime state for this slice.

## UNKNOWN

- not rendered as a normal hex;
- cannot be targeted by normal movement;
- hidden content not instantiated into player-facing UI;
- may contain authored distant Landmark observation metadata.

## OBSERVED

Player knows rough existence/category but not complete information.

Examples:

- rough terrain silhouette;
- Stone barrier visible;
- distant Spire bearing;
- habitat cue without exact resource identification.

## DISCOVERED

Hero has physically reached/clearly revealed the hex.

- terrain is known;
- normal pathfinding can use it if traversable;
- visible objects can become interactable.

## UNDERSTOOD

The player understands the important rule/meaning of that place.

Examples:

- Camp;
- mastered resource source;
- Landmark after Insight;
- known shortcut/gate.

## Reveal rule for v0.1

After each executed movement step:

1. entered hex becomes `DISCOVERED`;
2. generated adjacent hexes become `OBSERVED` unless blocked by an occlusion rule;
3. content visibility is evaluated separately;
4. distant Landmark observation may be added by Landmark visibility rules;
5. if a **significant reveal** occurs and Scout Awareness is enabled, movement pauses before the next step.

Significant reveal types:

- newly observed threat;
- new Landmark Promise;
- new traversal blocker on active route;
- previously unknown interactable resource habitat at route decision distance;
- combat detection;
- authored discovery marked `interruptMovement=true`.

# 10. Path of Will — Exploration Turn Model

This slice uses the newer Will state model:

```ts
type WillState = 'GATHERED' | 'COMMITTED' | 'DISPERSED' | 'GATHERING';
```

Do not implement a numeric Will pool.

## 10.1 Exploration Burst

A **Burst** is the complete exploration action cycle while Will is available.

Candidate rule for this slice:

```text
0..N Shift steps
→ at most 1 Act
→ remaining Shift steps
→ End Burst
```

The Act can also happen before any movement.

For the fixture:

```ts
scoutRouteLimit = 5;
maxActsPerBurst = 1;
```

`5` is a literal count of hex steps, therefore its display is allowed under the no-abstract-numbers philosophy.

## 10.2 Burst state

```ts
interface MovementBurstState {
  id: string;
  routeLimit: number;
  stepsUsed: number;
  stepsRemaining: number;
  actUsed: boolean;
  executedPath: HexCoord[];
  previewPath?: HexCoord[];
  pausedReason?: 'SIGNIFICANT_REVEAL' | 'PLAYER_STOP' | 'INTERACTION' | 'COMBAT_TRANSITION';
}
```

## 10.3 Will transitions

```text
Enter World:
  GATHERED

First Shift/Act of Burst:
  GATHERED → COMMITTED

Burst voluntarily or automatically ends:
  COMMITTED → DISPERSED

Gather Will selected:
  DISPERSED → GATHERING

World Pulse resolves without Combat transition:
  GATHERING → GATHERED
```

Invalid transitions must be rejected with a semantic reason.

## 10.4 When Burst ends

Burst ends when any of the following occurs:

- player selects `End Burst`;
- route steps reach zero and no unresolved Act remains relevant;
- player uses Act and explicitly ends instead of using remaining movement;
- combat transition starts;
- authored hard stop occurs.

An interaction does **not** automatically erase unused movement.

Example:

```text
Move 2
→ Pickaxe / Break Stone Crust
→ Move 3 through new passage
→ End Burst
```

## 10.5 Gather Will

Gather Will is only available when:

- Hero Will is `DISPERSED`;
- no unresolved movement/interaction exists;
- Hero is not already detected/in Combat transition;
- no authored rule blocks it.

Flow:

```text
Select Will Sigil / Gather Will
→ preview known immediate response where rules allow
→ commit
→ Will = GATHERING
→ resolve one World Pulse
→ if no Combat: Will = GATHERED
```

Gather Will is not sleep and does not restore arbitrary resources.

It is the moment when the player accepts a world response in exchange for another Burst.

# 11. Scout Profile Used by the Slice

The slice tests Scout as route mastery, not only distance.

```ts
interface ScoutExplorationProfile {
  routeLimit: number; // 5 in fixture
  waypoint: boolean; // true
  awarenessInterrupt: boolean; // true
  trailSense: boolean; // true for known consequences only
  frontierReading: boolean; // limited, authored cues only
}
```

Fixture profile:

```ts
const STARTER_SLICE_SCOUT: ScoutExplorationProfile = {
  routeLimit: 5,
  waypoint: true,
  awarenessInterrupt: true,
  trailSense: true,
  frontierReading: true,
};
```

This profile is **not** the final progression ladder. It exists to test whether the capabilities themselves are fun.

## Waypoint

Player may add one intermediate hex to route preview.

The pathfinder solves:

```text
Hero → Waypoint → Destination
```

The player never needs to manually click every hex.

## Awareness Interrupt

If significant information is revealed mid-route:

```text
PAUSE MOVEMENT
→ Continue
→ Stop
→ Act (if a valid token interaction is available)
```

Unused steps remain available if execution continues within the same Burst.

## Trail Sense

Route preview may show **known** semantic consequences only.

Examples:

- `Breakable shortcut nearby`;
- `Known Patrol crossing`;
- `Shelter`;
- `Known Frayed gate`.

It must never reveal hidden enemy coordinates or hidden resource nodes.

On hover/selection:

- final hex is green if reachable this Burst;
- red if not legally reachable;
- final hex displays total required step count;
- trail is drawn using existing trail renderer;

```text

```

- `△` = known terrain/gate consequence;
- `!` = known threat/decision gate;

Do not display hidden probability or numeric danger.

# 13. Interaction Grammar in the Slice

## 13.1 Hand holders

The Hero Board remains the source of currently held tools.

Example fixture loadout:

```text
LEFT HAND HOLDER  → Hand / empty interaction hand
RIGHT HAND HOLDER → Pickaxe
```

If the existing implementation represents Hands as always-present tokens and equipment inserted into a Hand holder, retain that exact interaction model.

## 13.2 Adjacent interaction rule

For this slice, world-object interaction requires:

- Hero on a neighboring hex;
- Tool/Hand token placed/rotated to overlap the target;
- a legal contextual verb.

No range interaction is introduced.

## 13.3 Required verb mappings

```text
Hand + Medicinal Plant Source
  → Take

Pickaxe + Stone Crust
  → Break Through

Hand + Marked Seam Trace
  → Inspect

Hand + Broken Pickaxe Trace
  → Inspect

Hand + Rope Anchor Trace
  → Inspect

Hand + Broken Spire interaction point
  → Inspect

Pickaxe + Old Marked Ridge
  before Insight  → no Break Seam verb
  after Insight   → Break Seam
```

Unavailable verbs must explain the concrete reason.

Bad:

```text
Invalid action
```

Good:

```text
The stone is solid; your Hero does not yet recognize a breakable seam.
```

# 14. Terrain Grammar Used by the Slice

```ts
type TerrainKind =
  'GROUND' | 'RUIN' | 'STONE_MASS' | 'STONE_CRUST' | 'BROKEN_PASSAGE' | 'VEGETATION';

type TraversalState = 'OPEN' | 'BLOCKED' | 'DESTRUCTIBLE';
```

## Stone Mass

- blocks movement;
- normal Pickaxe cannot open it;
- creates map shape and occlusion;
- old marked ridge remains Stone Mass until knowledge recontextualizes the seam interaction.

## Stone Crust

- blocks movement;
- can be broken with Pickaxe;
- one Act;
- creates permanent Broken Passage;
- creates Stone Fragment;
- creates CARRYING Noise;
- invalidates route/path caches immediately.

## Broken Passage

- traversable;
- persistent across save/load;
- usable by Hero and Patrol if their movement rules permit it;
- becomes part of Trail Imprint / Known Travel after traversal.

## Ruin Shelter

For the vertical slice only:

- traversable;
- marks a readable sheltered position;
- blocks direct Patrol line-of-sight through its solid side geometry;
- does not create an abstract defense bonus.

Exact visual wall-edge occlusion may use existing terrain collision/LOS primitives. If those do not yet exist, fixture-specific occlusion edges are allowed behind a generic interface.

# 15. Stone Crust Transformation

Command intent:

```ts
UseToolOnWorldTargetCommand {
  heroId,
  toolId: 'PICKAXE_STARTER',
  targetHex: { q: 3, r: 0 },
  verb: 'BREAK_THROUGH'
}
```

Validation:

1. Hero adjacent;
2. Pickaxe currently available in correct Hand holder;
3. Hero has an unused Act in the current Burst;
4. target terrain is `STONE_CRUST`;
5. target state is still `DESTRUCTIBLE`;
6. command state version is current.

Execution:

```text
STONE_CRUST
→ BROKEN_PASSAGE
→ traversal BLOCKED becomes OPEN
→ create Stone Fragment token/source event
→ create CARRYING Noise at (3,0)
→ create persistent Disturbance reference
→ invalidate pathfinding
→ invalidate known-route qualification for affected segments
→ emit semantic Rule Trace
```

Semantic trace:

```text
Pickaxe
→ Stone Crust
→ seam breaks
→ passage opens
→ Stone Fragment released
→ Echo created
→ routes recalculated
```

No HP/durability bar is needed for this first crust.

```ts
type ResourceId = 'MEDICINAL_PLANT' | 'STONE_FRAGMENT' | 'TIMBER';
```

Only `MEDICINAL_PLANT` and `STONE_FRAGMENT` need actual world interactions in this fixture.

`TIMBER` contract is implemented because it is part of the starter resource grammar, but no tree-harvest gameplay is added to this slice.

## 16.2 Medicinal Plant habitat

Location:

```text
(3,-2) adjacent to the Ruin Shelter
```

Role:

- creates a small route deviation;
- teaches that resources belong to habitats;
- provides a downstream Healing input;
- does not require a separate harvesting mini-game.

Interaction:

```text
Hand → Medicinal Plant → Take
```

Result:

- source state changes visibly;
- one Medicinal Plant enters inventory/resource stack;
- knowledge record advances as configured;
- no World Pulse occurs automatically;
- the Act is consumed for the current Burst.

The plant must be placed in a readable environment combination, for example:

```text
ruin shade + vegetation/moist ground cue
```

Do not add a floating `MEDICINAL RESOURCE HERE` marker before discovery.

Created as a by-product of Stone Crust destruction.

It may use routine pickup:

```text
Hand → Stone Fragment → Take
```

If inventory auto-collection is already canonical for transformation by-products, that can be A/B tested, but the player-facing state change must remain clear.

## 16.5 Resource knowledge

# 17. Landmark Promise — Broken Spire

`Broken Spire` is a **Regional Landmark**.

It must satisfy:

```text
Promise → Approach → Interaction → Insight
```

## Promise

From the Camp frontier / Region A, the player may see a distant silhouette or bearing.

The UI may communicate:

```text
A broken vertical silhouette beyond the ridge
```

It must not show:

```text
Broken Spire — 11 hexes — Quest Objective
```

## Approach

At least two meaningful route approaches exist:

1. long/sheltered north path;
2. shorter Stone Crust route if the player uses Pickaxe.

Patrol timing and Medicinal habitat add secondary decisions.

## Interaction

The Landmark itself does not open a reward chest.

The player interacts with nearby Traces and the Spire inspection point using the existing Hand grammar.

# 19. Recontextualization

When `WEAKENED_SEAM_MARK` becomes `UNDERSTOOD`:

1. scan only previously known/observed world entities tagged with compatible mark semantics;
2. detect `old_marked_ridge (1,-1)`;
3. attach a small `Memory Spark` / reconsideration state;
4. do not reveal any hidden destination beyond the ridge;
5. do not auto-open the route;
6. do not teleport the Hero back.

The old ridge changes interaction grammar:

Before Insight:

```text

→ no Break Seam
```

After Insight:

```text
Pickaxe + old ridge
→ Break Seam
```

Applying the Insight:

```text
Stone Mass with weakened-seam semantic
→ Broken Passage
→ hidden local pocket / future route becomes discoverable
```

For v0.1 the passage beyond may terminate in a small topology reward or sealed test pocket. Do not generate a third full Region.

This is the key knowledge-progression proof:

> **The world did not gain a new object. The player gained a new understanding of an object that was already there.**

# 22. World Pulse

## 22.1 Trigger

Normal gameplay v0.1 trigger:

```text

```

## 22.2 Response budget

```ts

  maxMeaningfulLocalResponses: 2,

```

A Pulse should normally create `0..2` meaningful local state changes.

## 22.3 Candidate response priority

1. combat/detection-critical legal response;
2. visible/known threat intent continuation;
3. Noise investigation;
4. default Patrol movement;
5. signal decay;
6. low-value presentation-only updates.

## 22.4 Stone Noise response

If the Patrol can perceive the active CARRYING Noise:

```text
PATROL mode
→ INVESTIGATE
→ target = Noise source
→ move one legal Patrol step toward source on the Pulse
```

If no legal route exists:

- do not teleport;
- retain/fallback to Patrol behavior;
- explain only if this is decision-relevant.

## 22.5 Fairness guards

The Pulse may not:

- spawn a new enemy behind the Hero;
- increase hidden detection rules because “tension is low”;
- seal the only Camp route without an authored recovery;
- regenerate harvested Medicinal Plant from repeated Gather Will;
- move an observed Patrol using a different rule than its shown intent unless world state changed;
- exceed the response budget for ordinary Pulse resolution.

## 24.2 Route qualification

A route segment becomes `KNOWN` when:

- it has been physically traversed;
- all required topology is discovered;
- traversal dependencies are known;
- relevant gates are identified.

It becomes `RELIABLE` when:

- no unresolved decision gate remains;
- required tools/capabilities are currently satisfiable;
- no known active threat makes automatic traversal unsafe;
- route world-state versions are current.

# 25. Known Travel in the Slice

The vertical slice needs enough Known Travel to prove:

> **Discovery once → navigation gets easier, but unresolved world consequences are never skipped.**

## 25.1 Travel Modes

Implement the contracts for:

```ts
type TravelMode = 'STRIDE' | 'VEIL' | 'SURVEY';
```

For this fixture:

### STRIDE

Prefers:

- reliable route;
- shortest known path;
- fewest unresolved gates.

### VEIL

Prefers:

- known sheltered path;
- avoidance of observed Patrol attention/crossings;
- may accept a longer route.

### SURVEY

Used primarily to move along known space toward Frontier while allowing significant discovery interruption.

No `GATHER` travel mode in v0.1.

## 25.2 Accelerated travel

Accelerated travel:

- animates Hero Token through physical Route Thread;
- compresses timing across solved segments;
- does not teleport;
- advances required world beats deterministically;
- stops at Decision Gates;
- stops on combat detection;
- stops on Memory Spark if configured as relevant;
- stops when route becomes Frayed.

# 26. Frayed Route

A route becomes `FRAYED` when a previously reliable assumption no longer holds.

Required reasons for the slice:

```ts
type RouteFrayReason =
  | 'KNOWN_THREAT_BLOCKING'
  | 'TOPOLOGY_CHANGED'
  | 'NEW_RECONTEXTUALIZATION'
  | 'COMBAT_DETECTION_RISK';
```

Starter return event:

- Hero has reached/understood Broken Spire;
- a return Route Thread exists;
- World Pulse/Patrol state places the observed Patrol at or adjacent to a critical crossing;
- STRIDE route is marked Frayed at that segment;
- accelerated return stops before the gate;
- player can choose an alternate sheltered route, wait through a new Burst/Pulse sequence, manipulate Noise if possible, or accept Combat.

The game must explain:

```text
Known Route
→ Patrol now controls this crossing
→ Route is Frayed here
→ travel stops before the unresolved decision
```

Do not show generic `Fast travel unavailable`.

# 27. Continue / Return Decision

Do not implement a numeric expedition risk meter.

The decision is derived from visible facts.

```ts
type ExpeditionPressureFact =
  | { type: 'VITALITY_DAMAGED' }
  | { type: 'PROTECTION_DAMAGED' }
  | { type: 'CAPABILITY_UNAVAILABLE'; capabilityId: string }
  | { type: 'RETURN_ROUTE_FRAYED'; routeId: string; reason: string }
  | { type: 'KNOWN_THREAT_ON_RETURN'; threatId: string }
  | { type: 'WORLD_SIGNAL_ACTIVE'; signalId: string }
  | { type: 'CRITICAL_PAYLOAD_CARRIED'; payloadId: string }
  | { type: 'FRONTIER_UNCERTAINTY'; frontierAnchorId: string };
```

No weighted sum is calculated for player-facing decision making.

At the Broken Spire Decision Horizon, the player should be able to choose:

### Conservative

Return after Region A / Medicinal value without fully resolving Landmark mystery.

### Opportunistic

Reach and understand Broken Spire, then return through known routes.

### Committed

Use optional Critical Payload A/B variant or push to the Frontier Exit before return, accepting a more complicated homeward state.

If these choices do not feel meaningfully different, do not expand exploration scope.

# 34. Preview / Execution Parity Rule

**The same rule services must power preview and execution.**

Do not create:

- separate route rules for hover and movement;
- separate Patrol logic for intent preview and World Pulse;
- separate travel-gate logic for Known Travel preview and execution;
- UI-only knowledge flags that are not canonical game state.

Required service pattern:

```ts
preview(commandIntent, canonicalState)
  → ValidationResult + PredictedSemanticConsequences

execute(validCommand, canonicalState)
  → DomainEvents
```

Execution may differ only if canonical world state changes between preview and commit. The difference must be explainable.

# 35. Core Algorithms

## 35.1 Route preview

```text
INPUT:
  hero coord
  routeLimit/remaining steps
  waypoint optional
  traversal graph
  discovery rules
  current known threats

SOLVE:
  if waypoint exists:
    shortestLegal(hero, waypoint)
    + shortestLegal(waypoint, destination)
  else:
    shortestLegal(hero, destination)

ANNOTATE:
  known terrain consequences
  known gates
  known threat crossings
  total step count

RETURN:
  path
  reachableThisBurst
  semantic consequences
```

Pathfinder must treat Stone Crust as blocked until transformation commits.

## 35.2 Movement execution

For each step:

```text
validate next edge
→ move Hero
→ emit HeroMovedStep
→ update discovery
→ evaluate object/threat visibility
→ evaluate combat detection
→ evaluate significant reveal
→ if significant reveal and Awareness enabled: pause
→ else continue
```

Never pre-reveal all consequences at final destination if they depend on information discovered mid-route.

## 35.3 Discovery update

```text
entered hex → DISCOVERED
adjacent generated eligible hexes → OBSERVED
visible landmark promise → observation record
visible content → content-specific visibility evaluation
```

## 35.4 Noise perception

Starter internal reach by band:

```ts
LOCAL = 1;
CARRYING = 3;
ECHOING = future / not used;
```

Noise reach is not player-facing numeric UI.

Perception:

```text
if hexDistance(threat, signal.source) <= bandReach
AND propagation not blocked by configured hard rule
THEN signal is perceivable by threat
```

For v0.1 use deterministic fixture behavior. Do not build an acoustic simulation.

## 35.5 Patrol response selection

```text
if Hero currently detected:
  trigger Combat transition
else if active perceived Noise exists:
  mode = INVESTIGATE
  target = highest-priority active Noise
  move one legal step toward target
else if mode == INVESTIGATE and target resolved:
  mode = RETURN_TO_ROUTE
  move toward nearest deterministic route node
else:
  mode = PATROL
  advance one route node
```

No RNG.

## 35.6 World Pulse transaction

```text
Validate Gather Will
→ Will = GATHERING
→ create Pulse record
→ gather legal response candidates
→ score/priority order
→ apply response budget
→ execute deterministic selected responses
→ decay active signals
→ evaluate combat transition
→ if no combat: Will = GATHERED
→ complete Pulse record
```

World state update is atomic from the player's command perspective.

## 35.7 Route knowledge qualification

```text
TRAVERSED when edge/path physically executed

KNOWN when:
  traversal recorded
  topology discovered
  required gates known

RELIABLE when:
  KNOWN
  AND no unresolved gate
  AND required capability available
  AND no known unsafe threat crossing
  AND segment versions current

FRAYED when:
  previously KNOWN/RELIABLE assumption is invalidated
```

## 35.8 Mystery insight

```text
if trace_marked_seam.inspected
AND trace_broken_pickaxe.inspected
THEN make WEAKENED_SEAM_MARK insight available
```

The player confirms/understands the insight through contextual Mystery/Knowledge UI.

No three-answer multiple-choice question.

## 35.9 Recontextualization scan

On knowledge transition to `UNDERSTOOD`:

```text
query previously OBSERVED/DISCOVERED entities with matching semantic tags
→ filter by authored compatibility
→ create reconsideration links
→ show limited Memory Spark(s)
```

Fixture limit:

```ts
maxNewMemorySparksPerInsight = 1;
```

## 35.10 Known Travel execution

```text
resolve route graph
→ validate selected Travel Mode
→ validate each segment/gate against current world version
→ animate/compress solved segment
→ advance configured world travel beat
→ revalidate next gate
→ if changed/frayed/detected/recontextualized:
     stop before unresolved decision
→ otherwise continue
```

Never cross Unknown topology.

# 44. Property / Invariant Tests

These must hold globally for the slice.

## I1 — Determinism

Same committed state + same command + same seed/version = same result.

## I2 — No invisible known critical state

Any known state that changes a current player decision has a player-facing representation.

## I3 — Unknown information privacy

Preview cannot reveal hidden resource/threat/location data merely because the engine knows it.

## I4 — Persistent topology

Committed terrain mutation survives save/load and affects all path queries.

## I5 — Actor topology parity

Hero and Patrol cannot traverse a blocked hex unless their own explicit movement rule permits it.

## I6 — Preview = execution rules

No duplicate legality logic.

## I7 — World Pulse causal integrity

Every meaningful response has a valid cause chain.

## I8 — World Pulse response budget

Ordinary Pulse does not exceed configured meaningful-response budget.

## I9 — No local resource farm

Gather Will alone cannot restore source economy.

## I10 — Knowledge monotonicity

Normal play never silently forgets an understood Insight.

## I11 — Recontextualization does not spoil hidden reward

It may point to a previously seen clue/object, not reveal the unknown content behind it.

## I12 — Known Travel never skips unresolved decisions

Any changed Gate/threat/combat/recontextualization can stop acceleration before resolution.

## I13 — No rectangular player-facing map

UNKNOWN cells do not form a visible board boundary.

## I14 — One Burst / one Act

No exploit grants multiple normal Acts without an explicit future ability.

## I15 — No numeric risk abstraction

No player-facing `Risk %`, Travel Energy, Hunger, or Will meter appears.

# 47. Playtest Success Gates

The slice is **not** approved because it merely works technically.

It must pass these design gates.

## Gate A — Route Interest

At least two route strategies are repeatedly chosen for meaningful reasons other than aesthetics.

Fail signal:

> everyone always takes the same mathematically superior path.

## Gate B — Will / Pulse Tension

Players can explain why the location where they end a Burst matters.

Fail signal:

> Gather Will feels like an arbitrary refresh button.

## Gate C — Terrain Agency

Players understand and value the ability to create a route.

Fail signal:

> Stone break is only “save two clicks” or always mandatory.

## Gate D — World Response Legibility

Players can connect:

```text
my action → world signal → Patrol response
```

Fail signal:

> Patrol movement feels random or cheating.

## Gate E — Resource Relevance

Players can state why the Medicinal Plant matters without being shown a giant recipe UI.

Fail signal:

> resource feels like generic loot.

## Gate F — Landmark Curiosity

A meaningful percentage voluntarily pursues Broken Spire because of the world signal/silhouette.

Fail signal:

> players need an explicit objective arrow.

## Gate G — Knowledge Progression

Players understand that the Spire discovery changed how they can interpret old stone.

Fail signal:

> Memory Spark feels like a random quest marker or the connection is not understood.

## Gate H — Return Mastery

Return through known space is materially faster and less repetitive than first exploration.

Fail signal:

> return still feels like commute.

## Gate I — Frayed Route Fairness

Players accept the interruption because they can see why the route changed.

Fail signal:

> “fast travel randomly stopped.”

## Gate J — Low UI Friction

Players spend most attention on the board, not menus/panels.

Fail signal:

> understanding exploration requires constant Player Board switching.

## Gate K — No Feature Dependency

The slice is interesting without weather, hunger, mounts, complex ecology or procedural quests.

If it is not, first **Kill / Simplify / Tune** current systems before expanding.

# 53. Final Design Rule for This Slice

The implementation should continuously test this sentence:

> **The interesting part of movement is not that the Hero can walk farther.
