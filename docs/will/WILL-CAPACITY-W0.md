# W0 — стартова Воля 20/20 (окрема задача)

Рішення Олега (2026-11-10): **кожен гравець на старті має 20/20 Волі.** Базова ємність 20; пізніше її збільшуватимуть спорядження, навички тощо. Не пов'язано з крамницею, окремий коміт. Скіли перед роботою: `hexoflat-phase`, `hexoflat-engine`, `hexoflat-web-state`. **Не комітити**: Олег комітить сам, наприкінці дати commit message.

## 1. Як зараз

- `packages/engine/src/knowledge/math.ts`: `KNOWLEDGE_RULES = { startingWill: 20, capacity: 50, … }`. Новий герой має 20/50.
- Ємність **зберігається** в кожному герої: `progress.knowledge.capacity` (сервер, агрегат `progress`), створюється в `createKnowledgeState` через `effectiveWillCapacity(KNOWLEDGE_RULES.capacity)`. Схема вимагає `current <= capacity`.
- `effectiveWillCapacity(base, modifiers)` і тип `WillCapacityModifier` уже існують, але джерел модифікаторів нема.
- Агрегат `progress` має `schemaVersion: 5` (апкастери 1–4 у `aggregates/registry.ts`).
- Бойова Воля (20 на хід) — окреме правило бою, W0 її не чіпає.

## 3. Що зробити

1. **Engine.** `KNOWLEDGE_RULES.capacity: 20`. Тест-інваріант: `startingWill <= capacity`. Оновити тести, що чекають 50 (`knowledge/*.test.ts`, `skills/sacrifice-skill.test.ts` — там 50 як параметр за замовчуванням, перевірити, чи тест про конкретну ємність, чи довільну).
2. **Міграція `progress` v5 → v6** (`aggregates/registry.ts`, `schemaVersion: 6`): `knowledge.capacity = effectiveWillCapacity(KNOWLEDGE_RULES.capacity)`, `knowledge.current = min(current, capacity)`. Апкастер має обрізати **до** парсингу схеми (там `refine(current <= capacity)`). Тести апкастера: 47/50 → 20/20, 12/50 → 12/20, 20/50 → 20/20, `skills`/`skillProgress` не змінюються.
3. **Одне місце для ємності.** Функція на кшталт `willCapacityOf(...)` (зараз = база), яку пізніше розширять модифікатори зі спорядження й навичок. Правило для майбутніх джерел записати тут, але не реалізовувати: за зразком max-health bonus (`HeroModel.setMaxHealthBonus`) — підняття ємності Волі не дає, зняття обрізає `current` (чи пам'ятати «борг», як у здоров'я, — вирішить Олег разом із першим джерелом).
4. **Навички.** Варіанти жертви рахуються від ємності (30 % / 60 % / усе): при 20 це 6 / 12 / усе. Перевірити тести й тексти. Коментар у `skills/skill-content.ts` «Will capacity is 50» оновити. Ціни Bionic лишаються (прогрес жертви переноситься між рангами).
5. **Web.** Знайти захардкожені 50 (`composables/skill-tree-view.test.ts`, `use-hero-details.test.ts` тощо); `fake-player-server.ts` бере правила з engine, тож має працювати сам. Показ `20/20` у шапці Hero, лічильнику Книги й картці бою — через `will-number.vue`, без змін компонента.
6. **API.** Інтеграційні тести, що створюють героя або чекають 50; `seed-hero` / `hero-rollback`; перевірити, що старий рядок `progress` v5 читається й апкаститься до v6.
7. **E2E.** Пошук очікувань ємності 50 у `apps/playwright` (зараз явних не знайдено); прогнати групи, що торкаються Волі (`@hero`, Книга Волі), лише якщо змінюються testid чи тексти.
8. **Документи.** `CLAUDE.md` (абзац Path of Will: «start 20, capacity 50» → «start 20/20, capacity 20 + modifiers»), `docs/SKILL-TREE-V2-PLAN.md` (якщо згадує 50), скіл `hexoflat-engine`, якщо згадує ємність. `CONTENT_VERSION` не піднімати.
