## 1. Як бій працює зараз (реальні правила)

- **Старт.** `hex-world-map.vue` стежить за `isHeroInEnemyVision` (`combatStore.getEnemyTilesSeeingHero()` → `findEnemyTilesSeeingHero`, радіус `creature.visionRange`, за замовчуванням 3). Щойно герой у радіусі будь-якого ворога — `combatStore.startCombat()`: відкриває туман у радіусі зору ворогів і починає хід героя.
- **Бій на тій самій мапі підземелля**, без окремої дошки. Вороги — це `hexobject` на тайлах мапи; рух ворога переставляє `hexobject` між тайлами.
- **Ходи** — по черзі «герой / ворог» (`combatTurnSide`), без ініціативи. Бюджет ходу — 10 кроків (`getCombatMoveBudget`), таймер 30 с лише показується (`combatTurnEndsAt`), нічого не форсує.
- **Удар героя** — інструментом через hex-дію `ATTACK` (перетягування інструмента на ворога, `action-starters-registry.ts` → `worldMap.performHeroCombatAttack`). Шкода = `(hero.attack ?? 8) + skillBonuses.attack` × `attackMultiplier` зброї, мінус захист щита ворога, дроби з одним знаком.
- **Захист героя** — один маркер щита на сусідньому гексі (`BLOCK` → `placeCombatDefendMarker`); ставлячи його, герой віддає всі кроки, що лишились.
- **Хід ворога** (`ensureEnemyTurnResolution`): обирає випадковий гекс поруч з героєм (`findAttackOptions` + `pickRandom` з `rng('combat')`), іде, **чекає 5 с через `window.setTimeout`**, б'є (`attack` істоти мінус захист щита героя і `skillBonuses.defense`), потім відходить (`findRetreatOptions`). Ворог «автоматично ставить щит» на випадковий сусідній гекс (`syncEnemyAutoDefend`).
- **Перемога** — коли на мапі не лишилось ворогів (`hasLivingEnemies`); скелет у печері стає могилою (`GRAVE`), `hero.addKilled()`.
- **Поразка** — `heroStore.takeDamage` → якщо `currentHealth <= 0` → `worldMap.respawnHeroAtCamping()`: кінець бою, портал закривається з причиною `DEATH`, збережена локація стирається, герой оживає з 1 серцем у кемпі.
- **Збереження** — поля бою (`combatActive`, `combatMarkers`, …) лежать у тому самому localStorage-блобі, що й мапа (`world-map-store.saveToStorage` + `CombatSnapshot`), автозбереження через `$subscribe`.

## 3. Генератор: точки розширення

Генератор V0–V7 уже в trunk (`packages/engine/src/boards/pipeline/`), не на окремій гілці.

- **Рецепт** = `content/boards/models/*.ts` (`BoardRecipeInput`, схема `content/boards/recipe-schema.ts`): `frame`, `biome`, `fog` (`FOG | ALL_REVEALED | BY_REGION`), `willZone`, `stages`.
- **Етапи й реєстри** (`boards/pipeline/registry.ts`): `form` (`drawing`, `blobs`), `relief` (`drawing`, `lake`, `ridge`, `sea`), `bounds` (`void`, `wall`), `gates` (`drawing`, `entry`, `exits`), `objects` (`drawing`, `rules`), `checks` (`reachable`, `shape`, `required`). Нова деталь = файл у `pipeline/pieces/` + рядок у реєстрі.
- **Сід** — `boards/board-seed.ts`; кожна деталь отримує свій потік через `pieceStreamLabel(stage, kind, n)` + `deriveStream`. Тобто `encounterId + attempt` (R-FIELD-3) просто стає сідом рецепта.
- **Об'єкти** ставить `pieces/rules.ts`: правило `{ id, pick, count, where: { region, steps, spacing, next }, chance, required, when }`. «Слоту» як окремого поняття немає — це правило в `objects`. **Слот `encounter` (B6)** = або нове правило з `pick` на об'єкт-загін, або окрема деталь `objects: encounters` з місцями «біля скрині / прохід / перед порталом / глухий кут». Рекомендація: окрема деталь, бо їй потрібні власні місця й склад загону з контенту.
- **Туман** — `fog: 'BY_REGION'` у печері (`map/fog-service.ts`, регіони з `form`). Для бойової дошки: `fog: 'ALL_REVEALED'`.
- **Воля за крок** — `knowledge/will-zone.ts` (`willZoneCharges`: `willZone !== 'free' && !combatActive`) + `stepCost`. Дії мапи ATTACK 2 / SCOUT 1 лягають на наявний `willCost` hex-дій (`START_HEX_ACTION` + `transactKnowledge`).
- **Рельєф — головна прогалина.** `boards/terrain.ts` знає лише `ground | mountain | water`. Щебеню, уступу (висоти), олії, пилки немає ні як рельєфу, ні як об'єктів. B4 має додати їх (див. C6).

## 5. Що це означає для B1

- Геометрію не писати з нуля: `utils/hex-utils.ts` уже має odd-r ↔ axial, сусідів і відстань. `battle/hex-battle-geom.ts` додає лише кільце, дугу лучника й напрямок.

- Поразка в B1 емітить подію; підключення до `respawnHeroAtCamping` (портал `DEATH`) — у B6, тест-страховка вже є (§6).
- Рішення (28.10.2026, Олег): **C2** — смерть лише при 0 сердець, зроблено в B1; **C3** — навички в бою не діють до B3, новий ефект обирає Олег у B3.
